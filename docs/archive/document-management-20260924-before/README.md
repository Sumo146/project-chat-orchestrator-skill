# project-chat-orchestrator-skill

## 做什么

维护个人Codex Skill `project-chat-orchestrator`。该Skill让当前项目主控对话在用户确认后创建普通方案讨论、执行和审查对话，分发任务、检查状态、安排返工并统一向用户汇报。

## 怎么使用

源文件位于`skill/project-chat-orchestrator/SKILL.md`，安装目标为`C:\Users\14672\.agents\skills\project-chat-orchestrator\SKILL.md`。

在项目主对话中明确调用`project-chat-orchestrator`，或者明确要求主对话另开普通对话执行已经确认的方案。Skill会先给出对话数量、角色、职责、任务边界、模型、推理等级和并发批次建议，最终由用户统一确认后才创建对话。

## 依赖

- Codex桌面端
- 普通项目对话的创建、主控到子对话的发送和用户触发读取能力
- 当前主对话属于目标Codex项目
- 已确认本次任务的项目文件范围和各路径权限
- 项目需要的路径已处于当前Codex项目可访问范围
- 当前环境要求的项目规则文件已经确认

## 目录

- `AGENTS.md`：本项目维护约束
- `skill/project-chat-orchestrator/SKILL.md`：可安装Skill源文件
- `docs/workflow-spec.md`：工作流设计和边界说明
- `docs/test-plan.md`：静态评测和真实侧边栏对话测试方案
- `evals/evals.json`：行为评测用例
- `evals/trigger-evals.json`：触发与不触发样例
- `WORKLOG.md`：变更记录

## 备注

- 执行对话是侧边栏中的普通项目对话，与主对话平级显示
- Codex项目可以是`Test`这类工作区大文件夹，逻辑项目可以是工作区下的独立子文件夹
- 项目文件可以集中在一个目录，也可以分散在多个已附加路径
- 主对话和执行对话同属一个Codex项目，并共同使用一次确认的项目文件范围
- 每个执行对话只分配完成任务需要的读写、只读路径，未分配路径默认禁止访问
- 默认不使用worktree
- Skill不会自动归档、删除、隐藏或重命名执行对话
- 执行对话使用稳定`threadId`追踪，用户手动改名后保留新标题，后续任务继续发送到原对话
- 项目接力记录保存任务编号、当前标题、`threadId`和可用时的`hostId`
- 当前存在待确认编排计划时，用户回复可以、开始执行等短语会续接分发；没有待确认计划时不会误触发
- 已分配给执行对话的实现任务由对应对话完成，主对话负责分发、检查、返工和汇总，不自行接手
- 默认采用一个主控加若干执行对话，方案讨论和审查对话按需创建，不固定要求完整角色组合
- 对话数量、角色和职责由用户最终决定，主控只提供建议
- 主控默认在分发后做一次即时或短时状态检查并结束运行，用户明确要求时可以持续等待和汇总
- 子对话只在自己的对话中保留进度、结果和待确认问题，不主动联系、唤醒、切换或导航到主控
- 主控可以主动读取子对话；默认短检查结束后不自行恢复，持续等待必须由用户明确要求
- 用户直接要求子对话承担职责外事项时，子对话先确认职责、路径、依赖和冲突变化，确认后更新任务记录再执行
- 新职责接管其他对话拥有的任务或文件时，由主控完成改派并确认原对话已经释放范围
- 子对话的职责变化不能解除禁止创建下一层对话、禁止启动Subagents和路径访问范围等硬限制
- 用户调用Skill或明确要求主控编排后，主对话进入持续有效的编排模式，直到用户明确退出、解除限制或确认项目完成
- 编排模式启用时，继续、开始执行、下一步等短指令只能推进分工、分发、检查和返工，不能授权主控直接实施
- 未分配的新任务必须先补充分工并让用户确认，不能默认由主控接手
- 协调记录保存编排模式、主控实施权限和任务负责人，跨会话后继续生效
- 每个新建对话必须在确认计划中写出具体模型、具体推理等级和建议依据，缺少配置时不得创建
- 静态评测检查结构、规则和触发边界；真实侧边栏对话测试必须先由用户确认测试对话数量、模型、推理等级和并发量
