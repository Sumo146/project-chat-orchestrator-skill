# project-chat-orchestrator工作流说明

## 目标形态

需要区分三个对象：

- Codex项目：侧边栏中的本地项目容器，绑定一个工作区文件夹，例如`Test → E:\Codex_Project\Test`
- 逻辑项目：用户在工作区中创建的独立项目文件夹，例如`E:\Codex_Project\Test\20260807-project-chat-orchestrator-skill`
- 项目文件范围：本次项目实际需要使用的目录和文件集合，可以是一个逻辑项目文件夹，也可以由多个分散路径组成

一个Codex项目可以包含多个逻辑项目，也可以附加多个相关文件夹。主对话和执行对话共享一份已确认的项目文件范围，不要求所有文件位于同一个目录。

```text
Codex项目Test
├─ [PCO]project-chat-orchestrator｜主控
├─ [PCO-E01]规则核验
└─ [PCO-E02]权限边界核验

项目文件范围
协调目录：E:\Codex_Project\Test\20260807-project-chat-orchestrator-skill
读写路径：E:\Codex_Project\Test\20260807-project-chat-orchestrator-skill
只读路径：可为空或包含其他已附加资料目录
排除路径：E:\Codex_Project\Test下的其他项目
```

这些对话在侧边栏中平级显示，不形成父子树。逻辑上的主从关系由任务编排建立。执行对话不是Codex内置Subagents。

## 推荐角色

```text
C00主控对话
├─E01至E0N执行对话
├─R01审查对话，可选
└─D01方案讨论对话，可选
```

- `C00`负责用户沟通、计划确认、分发、状态检查、返工和汇总
- `E01`至`E0N`负责具体任务
- `R01`默认只读审查，问题留在自身对话，由主控读取后安排原执行对话返工
- `D01`默认研究复杂方案，结论留在自身对话，由主控读取后进入执行计划

主控根据项目情况建议数量、角色、职责和并发批次，最终决定权属于用户。普通项目默认只创建主控和必要的执行对话，审查和方案讨论对话按风险、复杂度或用户要求创建。

用户默认通过主控沟通。用户明确进入子对话后可以直接参与，但任务依赖、分配和最终汇总仍由主控管理。

## 触发边界

### 应触发

- 用户明确调用`project-chat-orchestrator`
- 用户明确要求当前主对话另开、创建其他普通对话执行已经确定的项目方案
- 用户明确要求自己只和主对话沟通，由主对话管理其他执行对话
- 当前主对话已经给出本Skill执行计划并等待确认，用户用可以、开始执行、按这个做等短语确认当前计划
- 当前主对话或协调记录显示编排模式仍为启用，用户用继续、下一步、接着做等短指令要求推进项目

### 不应触发

- 用户只要求做项目方案，还没有要求另开对话执行
- 用户只说并行处理、分头处理，但没有要求创建普通侧边栏对话
- 用户明确要求使用Subagents、子代理或蜂群
- 用户只询问Codex多对话功能如何工作
- 普通编码、分析、审查或文件修改任务
- 当前不存在待确认编排计划且编排模式未启用时的普通确认语

## 编排模式锁

用户明确调用本Skill，或明确要求当前对话作为主控管理其他普通对话时，立即启用编排模式锁。锁在执行计划确认前就生效，并持续到用户明确退出、解除主控限制或确认整个项目完成。

锁启用时，主控默认没有实施权限，只负责方案、分工、分发、状态检查、验证、返工、记录和汇总。主控只能实施执行计划明确归属于自己的任务。

继续、开始、开始执行、按计划做、下一步、接着做和完成剩下的等泛化指令，只表示继续当前编排流程，不表示把实施任务改派给主控。

| 情况 | 处理 |
|---|---|
| 任务已有负责人 | 向原对话发送任务或续派 |
| 计划确认但对话未创建 | 按计划创建并分发 |
| 任务没有负责人 | 先补充分工、模型、推理等级和验收，让用户确认 |
| 执行对话不可访问 | 记录阻塞，不由主控接手 |
| 阶段完成但项目未完成 | 提出下一阶段分工，不由主控直接实施 |

只有用户明确要求退出本Skill、解除主控限制或把某个具体任务改派给主控亲自完成时，才能解除全部或单项限制。短指令不能解除锁。

协调记录保存编排模式、锁定范围、主控实施权限、任务负责人、启用依据和解除条件。跨会话或上下文压缩后先读取这些字段。记录为`active`时，即使当前消息没有再次点名Skill，仍按编排模式执行。

主控调用任何实施工具前检查锁状态、任务负责人和是否存在明确的主控任务授权。锁为启用且任务没有明确归属主控时，禁止修改实现文件或推进具体实现。

## 模型与推理等级

主对话模型不受Skill限制。每个执行对话的模型和推理等级都可以独立选择，也可以全部使用同一设置。

优先级如下：

1. 用户为某个执行对话指定的设置
2. 用户为全部执行对话指定的统一设置
3. 主对话给出的建议
4. 用户没有表达偏好时，模型默认`gpt-5.6-luna`，推理等级默认`medium`

主对话在一份执行计划中同时给出模型和推理等级建议，不拆成多轮重复确认。用户确认后，创建对话时使用确认值。

用户在执行对话中手动修改模型或推理等级后，主对话后续发送消息时不再携带这两个设置，保留执行对话当前值。只有用户明确要求主对话修改时才可覆盖。

## 对话数量和并发

主对话根据以下因素建议数量和并发批次：

- 可以独立验收的工作包数量
- 文件和模块是否重叠
- 前后依赖关系
- 共享配置、数据库迁移和公共接口的修改风险
- 协调成本是否超过并行收益

适合并行的任务必须边界清晰、文件所有权尽量不重叠。多个任务要修改同一文件时，改成串行批次，或把该文件交给一个执行对话统一修改。用户决定最终数量、角色、职责和并发方式。

## 单次确认

创建前由主对话集中展示一份执行计划，至少包括：

| 字段 | 内容 |
|---|---|
| 编号和名称 | 对话标题及任务编号 |
| 角色 | 主控、执行、审查或方案讨论 |
| 任务归属 | 每项任务由执行对话还是主对话负责 |
| 目标 | 每个执行对话必须完成的结果 |
| 项目范围 | 协调目录、默认工作目录、全部读写、只读和排除路径 |
| 对话文件边界 | 每个执行对话分配到的最小路径子集 |
| 验收 | 测试、检查项和完成条件 |
| 依赖 | 前置任务和执行批次 |
| 模型 | 每个对话或统一模型 |
| 推理等级 | 每个对话或统一等级 |
| 并发量 | 同时运行多少个对话 |
| 等待方式 | 默认分发后短检查并返回，或按用户明确要求持续等待 |
| 确认后动作 | 新建执行对话或向已有执行对话发送任务 |

每个新建对话必须单独写明具体模型、具体推理等级和简短建议依据。不能用默认、稍后确定或创建时再选代替具体值。用户没有指定时，按任务给出建议；没有更合适的建议时使用`gpt-5.6-luna`和`medium`。

复用已有对话时写明保留当前设置，后续发送消息不覆盖模型和推理等级。任一新建对话缺少具体模型或推理等级时，执行计划不能进入用户确认或创建阶段。

用户已经明确过的设置直接继承，不重复询问。只有缺少会影响创建的关键决定时才补入这次集中确认。确认后出现实质变更，只确认受影响部分。

## 确认续接和任务归属

执行计划记录等待确认、已确认、已分发、执行中、待检查、已完成等状态，并记录每项任务的负责人、目标`threadId`或待创建标记、确认后动作和主对话是否允许执行。

计划处于等待确认时，用户回复可以、开始执行、按这个做等短语，直接确认并续接当前计划，不重复询问已经明确的模型、推理等级、路径和并发量。编排模式锁启用时，继续、下一步等短指令也必须回到现有分工和状态中路由。只有没有待确认计划且锁未启用时，普通确认语才不触发Skill。

确认后的第一个业务动作是分发：已有执行对话时按`threadId`发送任务，没有对应对话时创建普通执行对话。分发完成前，主对话不修改已分配任务的实现文件，也不运行推进该任务实现的命令。

任务分配后，主对话负责讨论、检查、验证、返工和汇总。主对话只能亲自完成执行计划明确归属于自己的工作。用户明确改派某项任务后，主对话才可接手该项任务。

分发能力不可用、目标对话不可访问或稳定ID失效时，保留未分发状态并说明阻塞，不自动改成主对话执行。

分发完成后，主控默认做一次即时或短时状态检查，记录稳定ID、状态和最后检查时间后结束当前运行。用户明确要求等全部完成后再回复或持续等待时，主控可以主动等待、读取、检查和汇总执行对话，并说明等待期间当前运行会被占用。子对话始终不能主动联系或唤醒主控。

执行期间的新想法按影响处理：不冲突的内容进入下一批计划；修改相同文件的内容等待原任务完成；改变当前要求的内容发送给原执行对话并更新验收；推翻当前任务时先确认停止原任务再重新分配。

## 职责范围变更

用户拥有每个对话职责范围的最终决定权。用户直接要求子对话处理当前职责外事项时，子对话不能立即开始，需要先说明：

- 当前职责与新增职责
- 新增或改变的读写路径
- 与其他对话的文件、依赖和并发冲突
- 对原任务验收和进度的影响
- 需要更新的任务记录

用户再次明确确认后，子对话更新职责和协调记录再执行。首次提出职责外要求不同时视为确认。新增职责接管其他对话的文件或任务时，子对话在自身对话记录改派需求并暂停，等待主控下次状态检查时读取和完成改派。收到主控更新后的任务包并确认原范围已释放后才能继续。子对话不得自行联系或唤醒主控，也不能与原对话并行修改。职责调整不能解除禁止创建下一层普通对话、禁止启动Subagents、禁止继续分发和禁止访问Codex项目不可访问路径等硬限制。

## 项目文件范围确认

创建执行对话前，主对话确认：

- 当前对话所属的Codex项目及其可访问文件夹
- 协调目录，用于保存项目规则、工作日志和接力信息
- 默认工作目录
- 允许读写的目录和文件
- 允许只读的目录和文件
- 明确排除的目录和文件
- 每个路径适用的`AGENTS.md`或其他规则文件
- 所有执行对话都创建在同一个Codex项目中
- 所有必需路径都处于当前Codex项目可访问范围
- 默认使用本地共享目录模式，不创建worktree

主对话先根据用户消息、当前上下文、项目文档和可见文件推断项目文件范围。用户已经明确的路径和权限直接继承。范围清晰时，把推断结果直接放进一次性执行计划，不额外询问。存在多条候选路径、文件分散、读写权限不明确或协调目录无法判断时，在同一份执行计划中列出建议并让用户确认。

路径不在当前Codex项目可访问范围时，让用户决定添加该文件夹、替换路径或排除该部分。不能假装执行对话能够访问。

当前环境要求项目级`AGENTS.md`时，协调目录必须存在项目级规则文件。多路径分别存在规则文件时，任务包明确列出适用于每个路径的规则。辅助文件夹中的规则不能依赖自动发现。

每个执行对话只获得任务所需的最小范围。一个对话可以只写前端目录并只读接口文档，另一个对话可以只写后端目录。未分配路径默认禁止访问。

## 命名

```text
[项目简称]项目名称｜主控
[项目简称-D01]方案讨论名称
[项目简称-E01]任务名称
[项目简称-E02]任务名称
[项目简称-R01]审查名称
```

标题不写模型和推理等级。

命名格式只用于初次创建。用户可以手动修改执行对话标题，主对话保留用户的新标题，不自动改回，也不因为标题变化创建替代对话。

## 对话身份和追踪

执行对话以平台稳定对话ID为准，当前Codex任务工具中对应`threadId`。标题是侧边栏显示信息，不承担身份识别职责。

创建成功后，在协调目录的`HANDOFF.md`、`TASKS.md`或同类记录中保存：

- 任务编号
- 对话角色
- 当前职责
- 当前标题
- `threadId`
- 可用时的`hostId`
- 当前状态
- 当前批次
- 是否持续等待，默认否，用户明确要求时改为是
- 用户参与方式
- 最后检查时间

后续等待、读取、补充任务和返工先使用`threadId`定位，再读取当前标题用于汇报。用户改名后只更新记录中的当前标题，不修改任务编号、文件权限、模型、推理等级或通信目标。

多个执行对话可以出现相同标题，不能根据标题合并、替换或新建对话。跨会话接手时如果没有保存稳定ID且标题无法唯一匹配，先让用户确认候选对话，不按标题猜测。

## 执行任务包

新对话不会自动继承主对话历史。创建时必须发送完整任务包：

- 角色：普通方案讨论、执行或审查对话，不是主控对话
- Codex项目名称、协调目录和默认工作目录
- 允许读写、允许只读和排除路径
- 每个路径适用的工作区规则、项目级`AGENTS.md`和相关项目文件
- 背景、目标和交付物
- 文件所有权、禁止触碰范围和并发注意事项
- 验收标准和必须运行的检查
- 前置依赖和已知风险
- 禁止创建下一层普通对话、禁止启动Subagents、禁止继续分发任务
- 不回退其他对话或用户已有改动
- 不访问任务包未分配的路径
- 用户直接提出职责外事项时，先说明范围变化并单独确认，确认后更新任务记录再执行
- 接管其他对话的文件或任务时，在当前对话记录改派需求并暂停，等待主控读取和更新任务包
- 职责变化不能解除创建对话、启动代理和访问范围等硬限制
- 所有进度、结果、失败、风险和待确认问题只留在当前子对话
- 不主动向主控发送消息、通知、交接或任务，也不通过其他对话转发给主控
- 不唤醒、恢复、打开、切换、导航到或改变主控对话
- 不创建以主控为目标的自动消息或完成通知
- 结果报告格式：完成内容、修改文件、验证结果、未解决问题、风险

共享文档和公共配置只能分配给一个对话，或由主对话统一更新。

## 协调和收尾

主对话负责分发后的短状态检查、按需读取进度和结果、检查改动、安排返工并统一向用户汇报。发送返工或补充要求时，按稳定ID复用原执行对话，保留用户修改后的标题、模型和推理等级。分配给执行对话的实现问题默认发回原对话处理，主对话不直接代改。

主控默认不持续等待。分发、一次即时或短时状态检查和状态记录完成后结束当前运行。用户明确要求持续等待时，主控可以主动等待、读取、检查和汇总；没有明确要求时，任务尚未完成不能成为长期占用主控对话的理由。子对话无论在哪种等待方式下都不能主动联系、唤醒或操作主控。

项目完成后保留全部执行对话，不自动归档、删除、隐藏、重命名或移动。用户自行查看和管理侧边栏对话。
