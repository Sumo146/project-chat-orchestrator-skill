# project-chat-orchestrator-skill项目约束

## 项目目标

维护个人Skill `project-chat-orchestrator`的源文件、行为规范、评测用例和变更记录

## 文件边界

- `skill/project-chat-orchestrator/SKILL.md`是可安装Skill的唯一运行文件
- `docs/`只放设计说明，不复制到个人Skill目录
- `evals/`只放触发与行为评测，不复制到个人Skill目录
- `README.md`说明项目用途和维护方法
- `WORKLOG.md`只追加，不覆盖已有记录

## 修改规则

- 对话编排必须使用Codex桌面端普通项目对话，不得替换成Subagents
- 只有主对话可以创建普通方案讨论、执行和审查对话
- 执行对话不得创建下一层普通对话，也不得启动Subagents
- 默认推荐一个主控对话加若干执行对话，方案讨论对话和审查对话按项目需要创建，不得固定要求每个项目都具备全部角色
- 主对话可以建议对话数量、角色、职责、模型、推理等级和并发批次，最终决定权属于用户
- 每个对话的职责范围由用户最终决定，主对话不得把建议方案当作不可更改的固定分工
- 主对话默认在分发后做一次即时或短时状态检查并结束当前运行；用户明确要求持续等待时，可以主动等待、读取、检查和汇总子对话
- 子对话的进度、结果、失败、风险和待确认问题只留在当前子对话，不得主动向主对话发送消息、通知或交接，也不得通过其他对话间接联系主对话
- 子对话不得唤醒、恢复、打开、切换、导航到或改变主对话，不得创建以主对话为目标的自动消息或完成通知
- 用户明确调用本Skill或明确要求当前对话作为主控管理普通执行对话后，立即启用编排模式锁；在用户明确退出、解除锁或确认项目完成前持续有效
- 编排模式锁启用时，主对话默认没有实施权限，只能完成协调、分发、只读检查、验证、记录和执行计划明确归属主控的任务
- 编排模式锁启用时，继续、开始、开始执行、按计划做、做下一步等短指令只能解释为继续编排，不得解释为授权主对话亲自实施
- 已有负责人时必须把任务发送给原对话；没有负责人时必须先补充分工并让用户确认，不得由主对话直接执行
- 只有用户明确说退出编排模式、解除主控限制或把具体任务改派给主控亲自完成，才能解除相应限制；继续等泛化短指令不构成改派
- 协调记录必须保存编排模式锁状态、锁的适用范围、主控实施权限和任务负责人，跨会话或上下文压缩后先读取记录再行动
- 用户直接进入子对话并要求处理当前职责外事项时，子对话必须先说明职责变化、路径变化、依赖和冲突并单独取得用户确认，确认后更新任务记录再执行
- 新职责接管其他对话的文件或任务时，子对话必须在自身对话记录改派需求并暂停；主对话下次检查时读取并完成改派，子对话收到更新任务包并确认原范围释放后再执行
- 用户对职责扩展的确认不能解除禁止创建下一层普通对话、禁止启动Subagents、禁止越过当前Codex项目可访问范围等硬限制
- 主对话与执行对话必须属于同一个Codex项目，并使用同一份已确认的项目文件范围，默认不使用worktree
- 项目文件范围可以包含单个目录、多个目录或具体文件，并分别标注读写、只读和排除权限
- Codex项目可以绑定容纳多个逻辑项目的工作区根目录，不得强制把每个逻辑项目文件夹单独保存为Codex项目
- 执行任务包必须写明Codex项目、协调目录、默认工作目录、允许读写路径、允许只读路径、排除路径和适用规则文件
- 每个执行对话只获得完成自己任务所需的最小路径子集，不得访问未分配范围
- 未经用户明确确认，不创建任何执行对话
- 当前对话存在等待确认的编排计划时，用户回复可以、开始执行、按这个做等短确认语后，必须继续执行该计划的分发动作，不得由主对话接手已分配任务
- 任务一旦分配给执行对话，主对话不得修改该任务拥有的实现文件或自行完成实现，除非用户明确改派给主对话
- 用户确认后的第一个业务动作必须是创建执行对话或向已有执行对话发送任务，分发能力不可用时不得退回主对话自行执行
- 不自动归档、删除、隐藏或重命名执行对话
- 不在对话名称中写模型名或推理等级
- 执行对话身份以平台稳定对话ID为准，当前对应`threadId`，标题只用于侧边栏展示和人工识别
- 用户手动修改执行对话名称后，主对话不得改回旧名称，不得因标题变化新建替代对话，后续任务继续发送到原`threadId`
- 协调目录中的接力或任务记录应保存任务编号、当前标题、`threadId`和可用时的`hostId`
- 用户手动修改执行对话的模型或推理等级后，主对话不得覆盖
- 每个准备新建的普通对话必须在同一份确认计划中逐项写出具体模型、具体推理等级和建议依据；缺少任一项时不得进入确认或创建
- Skill触发范围必须保持窄，不得因普通并行任务或一般项目规划误触发
- 没有等待确认的编排计划且编排模式锁未启用时，单独出现可以、开始执行、继续等短语不得触发Skill
- 不修改工作区或全局`AGENTS.md`来实现Skill触发

## 文风

- 中文结论先行，信息紧凑
- 不使用空泛开场、讨好式肯定或模板化总结
- 不替用户做尚未授权的关键决定

## 校验

- 修改`SKILL.md`后检查YAML frontmatter、触发描述和关键禁止项
- 修改行为规则后同步更新`docs/workflow-spec.md`和`evals/evals.json`
- 安装前对比源文件和目标文件，安装后再次校验内容一致
